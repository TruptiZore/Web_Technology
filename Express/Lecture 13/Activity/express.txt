Q1))) diff betn package.json and package lock.json

| Feature         | package.json                              | package-lock.json                              |
| --------------- | ----------------------------------------- | ---------------------------------------------- |
| Purpose         | Defines project metadata and dependencies | Locks exact versions of dependencies           |
| Created By      | Developer (manually or npm init)          | Automatically generated by npm                 |
| Editable        | Yes (developer edits it)                  | No (auto-managed, should not edit manually)    |
| Version Info    | Flexible versions (e.g., `^1.0.0`)        | Exact versions (e.g., `1.0.2`)                 |
| Role            | Describes what the project needs          | Ensures same versions are installed            |
| File Size       | Smaller                                   | Larger (contains full dependency tree)         |
| Dependency Tree | Not detailed                              | Complete dependency tree with sub-dependencies |
| Used For        | Project setup and dependency declaration  | Consistent installation across systems         |


Simple Explanation ----
- package.json → “What dependencies your project needs”
- package-lock.json → “Exact versions that were installed”


Why package-lock.json is Important -------
    Ensures same dependency versions for all developers
    Prevents bugs due to version changes
    Makes builds reproducible


Q2))) diff betn dependencies and dev dependencies

| Feature                 | dependencies                         | dev Dependencies                       |
| ----------------------- | ------------------------------------ | -------------------------------------- |
| Purpose                 | Required for running the application | Required only during development       |
| Used In                 | Production + Development             | Development only                       |
| Installed in Production | Yes                                  | No                                     |
| Examples                | express, react, axios                | nodemon, jest, eslint                  |
| Command                 | `npm install package`                | `npm install package --save-dev`       |
| Role                    | Core functionality of app            | Tools for testing, building, debugging |


Simple Explanation ----
- dependencies → Needed to run the app
- devDependencies → Needed to develop the app


Real Understanding -----

dependencies ----
    Used when app is running :
        Web server (Express)
        UI library (React)
        API calls (Axios)

devDependencies -----
    Used during development :
        nodemon → auto restart server
        eslint → code checking
        jest → testing


Q3))) types of routing methods.

What is Routing?
Routing is the process of handling client requests (URL + HTTP method) and sending the correct response.
Example :
When user visits /home, server decides what to show.

Types of Routing Methods (HTTP Methods) ----
These are the main routing methods used in applications:

1. GET Method ------
Used to retrieve data from server
Does NOT modify data
Example :
    app.get('/users', (req, res) => {
        res.send("Get all users");
    });


2. POST Method -------
Used to send data to server
Creates new resource
Example :
    app.post('/users', (req, res) => {
        res.send("User created");
    });


3. PUT Method -------
Used to update entire data
Example :
    app.put('/users/1', (req, res) => {
        res.send("User updated");
    });


4. PATCH Method ------
Used to update partial data
Example :
    app.patch('/users/1', (req, res) => {
        res.send("User partially updated");
    });


5. DELETE Method ------
Used to delete data
Example :
    app.delete('/users/1', (req, res) => {
        res.send("User deleted");
    });


6. ALL Method -------
Handles all HTTP methods
Example :
    app.all('/test', (req, res) => {
        res.send("Handles all methods");
    });


| Method | Purpose             |
| ------ | ------------------- |
| GET    | Fetch data          |
| POST   | Create data         |
| PUT    | Update full data    |
| PATCH  | Update partial data |
| DELETE | Remove data         |
| ALL    | Handle all methods  |


Q4))) diff betn post() and patch()


| Feature       | POST()                                          | PATCH()                               |
| ------------- | ----------------------------------------------- | ------------------------------------- |
| Purpose       | Create new resource                             | Update existing resource (partial)    |
| Operation     | Insert data                                     | Modify specific fields                |
| Data Handling | Sends full data for new entry                   | Sends only fields to update           |
| Idempotent    | No (multiple calls create multiple resources)   | Yes (same update gives same result)   |
| Used When     | Adding new user/product                         | Updating part of user/product         |
| Example       | Create new account                              | Update email or password              |


Real-World Example ----
POST ----
    Register user
    Add product
    Submit form
PATCH ----
    Update profile name
    Change password
    Update address


Q5))) diff betn put() and patch() 

| Feature    | PUT()                             | PATCH()                            |
| ---------- | --------------------------------- | ---------------------------------- |
| Purpose    | Update entire resource            | Update partial resource            |
| Data Sent  | Full object/data                  | Only required fields               |
| Operation  | Replaces existing data completely | Modifies specific fields only      |
| Idempotent | Yes                               | Yes (generally)                    |
| Risk       | May overwrite existing data       | Safer (only changes needed fields) |
| Used When  | Updating full record              | Updating small part of record      |


Real-World Example -----
PUT ----
    Update full profile
    Replace entire product details
PATCH ----
    Change only password
    Update only email or address


Q6))) port write in .env file

What is .env file?
A .env file is used to store environment variables like :
    Port number
    Database URL
    API keys

So you don’t hardcode them in your code.

Install dotenv (if not installed) :
        -- npm install dotenv

ex ----
require('dotenv').config();   // Load .env file

const express = require('express');
const app = express();

// Use PORT from .env or default 5000
const PORT = process.env.PORT || 5000;

app.get('/', (req, res) => {
    res.send("Server is running");
});

app.listen(PORT, () => {
    console.log(`Server running on port ${PORT}`);
});


How It Works --------
.env → stores PORT
process.env.PORT → reads value
dotenv.config() → loads variables into app
